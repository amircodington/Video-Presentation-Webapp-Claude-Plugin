02

The pipeline

The key idea, taken from Screen Studio, Recordly and Pagecast: record clean, direct later. The browser is filmed with no effects, while a log notes where every click, scroll and element was. All camera motion, cursor, callouts and subtitles are then added in HyperFrames from that log, so every take is reproducible and sharp.

Why not zoom live?

CSS zoom or page.mouse tricks during recording change layout, look jumpy and must be re-recorded for every tweak. In post, a zoom is just a GSAP tween on the video layer and costs a 30-second re-render.

Why record at 2× density?

A 2× zoom on 1× footage is blurry. Recording at deviceScaleFactor: 2 keeps text crisp at up to 2× camera zoom in a 1080p output.

Why subtitles from the scenario?

The video is silent, so there is no speech to transcribe. Each beat's say: line already has a start and end time from the event log, which turns straight into SRT and VTT cues.

04

Desktop or mobile

The first question decides the browser setup and the final frame. Playwright's device emulation handles mobile touch, user agent and pixel density.

1920 × 108016:9 output

Browser viewport 1440×810 at density 2, so the raw take is 2880×1620. Framed inside a browser window on a soft background, with a 6 to 10% margin so zooms have room to breathe.

1080 × 19209:16 output

Emulated phone viewport 390×844 at density 3 (iPhone 15 class), touch enabled, mobile user agent. Taps show as a touch dot instead of an arrow cursor.

05

Camera math

The director reads each element's box from events.json and computes a camera keyframe. The red frame below is the camera; it eases from the full page to the element with some padding.

// one camera move per beat
const pad = 1.6;                 // show context
const zoom = Math.min(
  2.2,                           // sharpness limit
  W / (box.w * pad), H / (box.h * pad));
const cx = box.x + box.w / 2;
const cy = box.y + box.h / 2;
tl.to("#take", {
  scale: zoom,
  x: W/2 - cx*zoom, y: H/2 - cy*zoom,
  duration: 0.9, ease: "power3.inOut"
}, beat.t - 0.45);             // lead the click
Cursor

Drawn in HyperFrames, never recorded. It travels on a slight bezier arc, 400 to 1200 ms by distance, with a ripple on each click (the Jodit recorder's numbers).

Dead time

Waits for network or loading are cut or sped up 4× using the idle gaps in the log, so the final pacing stays brisk.

Explanatory motion

Callout labels, a spotlight dim around the target, and chapter title cards between features, from the HyperFrames block registry.

06

The scenario file

One YAML file is the single source of truth. Claude writes it after exploring the app, you edit it in plain language, and every later step reads it.

video:
  format: desktop            # or mobile
  url: https://panel.example.com
  auth: .demo/auth.json
  subtitles: [en, fa]
  style: { background: soft-gradient, frame: browser, accent: "#2747D9" }
scenes:
  - id: dashboard
    title: Everything at a glance       # chapter card
    beats:
      - { do: goto, path: /dashboard, camera: wide,
          say: { en: "The dashboard shows every account at a glance.",
                 fa: "داشبورد همه‌ی حساب‌ها را یک‌جا نشان می‌دهد." } }
      - { do: hover, target: "role=region[name='Balance']", camera: focus,
          callout: "Live balance", say: { en: "Balances update in real time." } }
  - id: export
    beats:
      - { do: click, target: "role=button[name='Export']", camera: focus, hold: 1.5,
          say: { en: "Export the report with one click." } }
      - { do: type, target: "label=Search", text: "BTC", speed: human }

# Demo Director

## Always start by asking
1. Desktop (16:9, 1920x1080) or mobile (9:16, 1080x1920)? Never assume.
2. The app URL and whether it needs a login. If it does, run
   `node scripts/record.mjs --login` so the user signs in once; store
   `.demo/auth.json` and never echo credentials.
3. Subtitle language(s) and target length (default 60–90 s).

## Steps
1. Discover: open the app with playwright-cli, list routes and features,
   take one screenshot per page. Prefer role/label selectors.
2. Scenario: write `.demo/scenario.yaml` (see templates/scenario.example.yaml).
   One scene per feature, 2–5 beats each, every beat has a `say` line of
   at most 12 words per language. Show it as a table and wait for approval.
3. Rehearse: `node scripts/record.mjs --dry-run`. Fix failing selectors; do
   not change the story without asking.
4. Record: `node scripts/record.mjs` → `.demo/raw.mp4` + `.demo/events.json`.
5. Direct: `node scripts/direct.mjs` → camera and cursor keyframes.
6. Compose and check: `node scripts/compose.mjs`, then a HyperFrames snapshot
   of one frame per scene. Show the storyboard before the final render.
7. Render: HyperFrames render, no audio track, then
   `node scripts/subtitles.mjs` → `out/demo.<lang>.srt` and `.vtt`.

## Rules
- Use demo or seeded data; never record real balances, emails or tokens.
- Max camera zoom 2.2x; every move eases in and out over 0.6–1.2 s.
- Hold 1.5 s after each important click so viewers can read.
- Subtitle cues: 1–2 lines, 42 characters per line max, 1.2 s minimum.
scenario-writer

Story before clicks

Orders features by value, not by menu order: hook in the first 5 seconds, core workflow, two "wow" features, closing shot of the dashboard. Writes subtitles in plain spoken language, Persian right-to-left safe.

camera-director

Taste rules for motion

Wide shot when a page loads, focus when acting, never zoom twice within 2 seconds, pan instead of zoom-out-zoom-in for neighbouring targets, and a slow push-in on the final frame.
